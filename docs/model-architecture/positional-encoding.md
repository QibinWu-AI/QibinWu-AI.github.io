# 位置编码演进史：从"给词编号"到"旋转空间"

> **核心问题**：Transformer 的自注意力机制是**排列等变**的——它把输入当成一个无序集合，"狗追猫"和"猫追狗"在它看来没有区别。位置编码就是给模型"装上眼睛"，让它知道词的先后顺序。

---

## 📜 总览：位置编码的五代演进

```
第一代 (2017)  绝对位置编码 · 正弦/学习式        ← "Attention Is All You Need"
第二代 (2018)  相对位置编码 · Shaw/T5             ← "位置不重要，距离才重要"
第三代 (2021)  旋转位置编码 · RoPE                ← "用旋转统一绝对与相对"
第四代 (2022)  线性偏置编码 · ALiBi               ← "不需要编码，直接加偏置"
第五代 (2024+) 上下文位置编码 · CoPE / 多维扩展    ← "位置由内容决定"
```

---

## 第一代：绝对位置编码（2017）

### 📄 论文：*Attention Is All You Need* (Vaswani et al., 2017)

### 核心思想

给每个位置分配一个**唯一的向量**，然后加到词嵌入上。就像给每个座位贴一个固定编号。

### 两种实现方式

| 方式 | 怎么做 | 优点 | 缺点 |
|------|--------|------|------|
| **学习式** | 为位置 1, 2, 3, ... 各学一个向量 | 简单直接 | 最大长度受限（学到了 512 就不能表示 513） |
| **正弦式** | 用 sin/cos 函数生成位置向量 | 可外推到更长序列 | 外推效果有限 |

### 正弦位置编码的公式

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```

- `pos` = 词在句子中的位置
- `i` = 嵌入向量的维度索引
- `d` = 模型维度
- `10000` = 基波长（实验确定）

### 通俗理解

想象一个**多频率的信号**：
- 低维度用**高频** sin/cos（变化快，区分相邻位置）
- 高维度用**低频** sin/cos（变化慢，区分远距离位置）

就像用"年-月-日-时-分-秒"来标记时间，每一级的粒度不同，组合起来就能唯一确定一个时刻。

### 关键发现：正弦编码里藏着旋转！

通过三角函数加法公式可以证明，正弦位置编码中位置 p 和位置 p+k 之间存在**线性变换关系**——而这个变换矩阵恰好就是**旋转矩阵**：

```
M_k = [cos(ωk)  -sin(ωk)]
      [sin(ωk)   cos(ωk)]
```

> 💡 这个发现埋伏了 4 年，直到 2021 年才被 RoPE 正式利用。

### 绝对位置编码的局限

1. **位置独立性**：位置 1 和位置 2 的编码，与位置 500 和位置 501 的编码，差异相同。但直觉上，相邻位置应该比远距离位置关系更密切
2. **长度限制**：学习式编码无法超越训练长度；正弦式编码理论上可外推，但实际效果有限
3. **加法污染**：位置向量直接加到词嵌入上，会改变嵌入的范数，干扰语义信息

## 第二代：相对位置编码（2018-2021）

### 📄 论文：*Self-Attention with Relative Position Representations* (Shaw et al., 2018) & *Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer* (T5, Raffel et al., 2019)

### 核心思想

**位置不重要，距离才重要**。不再给每个位置分配独立向量，而是关注两个词之间的**相对距离**。

### 通俗类比

- 绝对位置编码：像说"第 3 个词和第 5 个词"
- 相对位置编码：像说"这两个词隔了 2 个位置"——不管它们在句子的哪里

### Shaw 的方案（2018）

在注意力计算中，给 Q·K 的点积加上一个**相对位置偏置**：

```
Attention = softmax(Q·K^T + R_rel) · V
```

其中 R_rel 是根据 (位置i - 位置j) 查表得到的偏置矩阵。

### T5 的方案（2019）

更简洁：使用一组**可学习的偏置值** B_k，表示"距离为 k 的两个 token 之间的偏置"：

```
Attention = softmax(Q·K^T + B) · V
```

- B_1 = 距离为 1 的偏置
- B_2 = 距离为 2 的偏置
- ...（通常截断到某个最大距离，如 128）

### 相对位置编码的优势

- ✅ **平移不变性**：相同的相对距离总是对应相同的偏置
- ✅ **可扩展**：理论上可处理任意长度的序列
- ✅ **更符合语言直觉**：语言中词的关系更多取决于相对距离

### 相对位置编码的致命问题

1. **计算效率低**：需要创建成对的位置编码矩阵，对长序列计算量大
2. **KV 缓存不兼容**：每生成一个新 token，所有已有 token 的相对位置编码都会变化，导致 KV 缓存无法高效使用
3. **工程复杂**：相对位置编码需要修改注意力计算方式，不像绝对编码那样"加完就完"

> ⚠️ **KV 缓存问题**是相对位置编码在 LLM 中不被广泛采用的主要原因。推理时，KV 缓存要求已生成 token 的编码在新 token 生成时不变——绝对位置编码天然满足这一点，相对位置编码不满足。

## 第三代：旋转位置编码 RoPE（2021）

### 📄 论文：*RoFormer: Enhanced Transformer with Rotary Position Embedding* (Su et al., 2021)

### 核心思想

**用旋转统一绝对与相对**。不是给词嵌入加一个位置向量，而是对 Q 和 K 向量**施加旋转**——旋转角度与位置成正比。

### 关键洞察

在注意力计算中，真正重要的是 Q·K 的**点积**。点积的几何含义是：

```
a · b = |a| |b| cos(θ)
```

如果我们通过旋转改变两个向量之间的**夹角 θ**，就能调整它们的点积——而旋转**不改变向量的长度**，因此不会干扰语义信息。

### RoPE 的做法

1. 将 Q 或 K 向量分成**二维对**：(q₁,q₂), (q₃,q₄), ..., (q_{d-1},q_d)
2. 对每一对施加旋转，旋转角度 = 位置 × 频率

```
R(q, p) = [cos(pθ₁)  -sin(pθ₁)] [q₁]
           [sin(pθ₁)   cos(pθ₁)] [q₂]

           [cos(pθ₂)  -sin(pθ₂)] [q₃]
           [sin(pθ₂)   cos(pθ₂)] [q₄]

           ...                    ...

           [cos(pθ_{d/2})  -sin(pθ_{d/2})] [q_{d-1}]
           [sin(pθ_{d/2})   cos(pθ_{d/2})] [q_d]
```

其中 θ_i = 10000^(-2i/d)，与正弦位置编码的频率完全一致。

### 为什么 RoPE 同时编码了绝对和相对位置？

关键在于 Q·K 的点积计算。设位置 m 的 Q 向量和位置 n 的 K 向量分别旋转了 mθ 和 nθ，它们的点积只依赖于**相对位置 (m-n)**：

```
R(q,m) · R(k,n) = f(q, k, m-n)
```

- **绝对位置**：每个位置的旋转角度是唯一的（位置 5 旋转 5θ，位置 10 旋转 10θ）
- **相对位置**：点积只取决于两个位置的差值，与绝对位置无关

### 通俗类比

想象一个**时钟**：
- 每个词被放在时钟的一个位置上
- 位置 1 的词在 1 点钟方向，位置 2 在 2 点钟方向...
- 两个词的"注意力"取决于它们在时钟上的**角度差**
- 不管是 1 点和 3 点（差 2 小时），还是 5 点和 7 点（差 2 小时），角度差相同，注意力模式相同

### RoPE 的优势

| 特性 | 绝对位置编码 | 相对位置编码 | RoPE |
|------|------------|------------|------|
| 编码绝对位置 | ✅ | ❌ | ✅ |
| 编码相对位置 | ❌（间接） | ✅ | ✅ |
| KV 缓存兼容 | ✅ | ❌ | ✅ |
| 计算效率 | 高 | 低 | 高 |
| 可外推 | 有限 | 好 | 好 |
| 不改变向量范数 | ❌（加法） | — | ✅（旋转） |

### RoPE 的局限

1. **远程衰减**：随着相对距离增大，注意力自然衰减（这是特性也是限制）
2. **外推不完美**：虽然比绝对编码好，但超出训练长度后性能仍会下降
3. **低频分量问题**：DeepMind 的分析指出，模型主要关注低频分量，某些低频旋转反而能提升性能

### 采用 RoPE 的模型

LLaMA 1/2/3、PaLM、Qwen、DeepSeek-V2/V3/V4、Gemma、Mistral、Phi... 几乎所有 2023 年后的主流 LLM 都使用 RoPE。

## 第四代：线性偏置编码 ALiBi（2022）

### 📄 论文：*Train Short, Test Long: Attention with Linear Biases Enables Input Length Extrapolation* (Press et al., 2022)

### 核心思想

**不用位置编码向量，直接在注意力分数上加一个与距离成线性关系的偏置**。

### ALiBi 的做法

```
Attention = softmax(Q·K^T + m·[-(i-j)]) · V
```

- `m` 是一个**不可学习的斜率**，每个注意力头不同
- `-(i-j)` 是位置 i 和 j 之间的距离（取负，距离越远偏置越负）
- 距离越远 → 偏置越负 → 注意力越小

### 通俗理解

就像给注意力加了一个"距离惩罚"：近处的词关注得多，远处的词关注得少。而且这个惩罚是**线性的**——每远一步，惩罚固定增加。

### ALiBi 的惊人特性

- ✅ **零位置编码**：不需要任何位置嵌入向量
- ✅ **完美外推**：在 1024 长度上训练，可以直接在 2048+ 长度上推理，性能不降
- ✅ **极其简单**：只需在注意力分数上加一个线性偏置
- ✅ **训练更快**：省去了位置编码的计算

### ALiBi vs RoPE

| 特性 | ALiBi | RoPE |
|------|-------|------|
| 位置信息形式 | 加法偏置 | 乘法旋转 |
| 外推能力 | 极强（线性外推） | 需要额外技巧（NTK/YaRN） |
| 表达能力 | 较弱（只有线性衰减） | 较强（多频率） |
| 长程建模 | 线性衰减可能过强 | 多频率更灵活 |
| 主流采用 | 较少（BLOOM, MPT） | 广泛（LLaMA, Qwen 等） |

### 为什么 ALiBi 没有成为主流？

虽然外推能力极强，但 ALiBi 的**表达能力有限**——它只能提供线性的距离衰减，无法像 RoPE 那样通过多频率捕捉不同尺度的位置关系。在大多数实际任务中，RoPE 配合长度扩展技巧（NTK、YaRN）的效果更好。

## RoPE 的长度扩展技术

RoPE 虽然外推能力不如 ALiBi，但社区发展出了多种扩展上下文长度的方法：

### 1. 线性插值（Position Interpolation, PI）

**思路**：不改变 RoPE 的频率，而是将位置索引线性压缩到训练范围内。

```
原位置：0, 1, 2, ..., 8192
缩放后：0, 0.5, 1, ..., 4096  （缩放因子 s=2）
```

**问题**：均匀缩放所有频率，高频信息丢失严重。

### 2. NTK 感知插值（2023）

**思路**：不缩放位置，而是**改变 RoPE 的基频 θ**，让高频少缩放、低频多缩放。

```
θ_new = θ × α^(dim/(dim-2))
```

**优势**：保留了高频信息（近距离位置关系），只对低频做更多缩放。

### 3. YaRN（Yet another RoPE extensioN, 2023）

**思路**：结合外推和插值，对不同频率维度采用不同策略：
- **高频维度**：不做插值，直接外推（保留近距离精度）
- **低频维度**：做插值（保证远距离不越界）
- **中间维度**：用 ramp 函数平滑过渡

**效果**：比 NTK 更好，训练量减少 10 倍，训练步数减少 2.5 倍。

### 长度扩展方法对比

```
线性插值 PI  → 简单但丢高频
NTK 插值    → 保留高频，改基频
YaRN        → 分频段处理，最优但最复杂
```

## 第五代：上下文位置编码 CoPE 及多维扩展（2024+）

### 📄 论文：*Contextual Position Encoding: Learning to Count What's Important* (Golovneva et al., 2024)

### 核心思想

**位置不应该只由序列索引决定，还应该由内容决定**。传统位置编码是静态的——位置 5 的编码永远是同一个向量。CoPE 让位置编码**动态适应上下文**。

### 通俗理解

传统位置编码：数"这是第几个词"
CoPE：数"这是第几个**重要的**词"

比如在处理"虽然...但是..."这样的句式时，CoPE 可以学会只计算句子级别的位置，忽略句子内部的词。

### CoPE 的做法

1. 用门控机制决定哪些 token 参与位置计数
2. 累加门控值得到**浮点位置**
3. 在整数位置嵌入之间插值，得到最终位置编码

### 多维 RoPE 扩展

RoPE 天然支持多维扩展——对图像等 2D 数据，分别在 x 和 y 方向独立旋转：

```
1D: 旋转角度 = 位置 × 频率
2D: 旋转角度_x = x坐标 × 频率_x
    旋转角度_y = y坐标 × 频率_y
```

关键：**不同维度的分量对不能混用**，否则会混淆 x 和 y 的位置信息。

采用多维 RoPE 的模型：DeepSeek-VL2、Qwen-VL 等。

## DeepSeek 的位置编码创新：MLA + RoPE

### 📄 论文：*DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model* (2024)

DeepSeek-V2 引入了 **MLA（Multi-head Latent Attention）**，对位置编码的处理提出了新的挑战和解决方案。

### MLA 的核心问题

MLA 通过将 KV 压缩到低维潜在空间来节省显存，但 RoPE 的旋转操作与 KV 压缩不兼容——旋转后的向量无法再被压缩。

### DeepSeek 的解决方案

**将 RoPE 的旋转从压缩后的潜在空间中"剥离"出来**：

1. KV 先压缩到低维空间（与位置无关的部分）
2. RoPE 旋转单独处理（位置相关的部分）
3. 在注意力计算时，将两部分重新组合

这种"解耦 RoPE"的设计，让 MLA 和 RoPE 可以共存，是 DeepSeek-V2/V3/V4 的关键架构创新之一。

## 🧭 位置编码演进路线图

```
2017  正弦/学习式绝对位置编码
      │  问题：位置独立、长度受限、加法污染语义
      ▼
2018  相对位置编码 (Shaw)
      │  问题：KV 缓存不兼容、计算效率低
2019  T5 相对偏置
      │
      ▼
2021  RoPE 旋转位置编码 ←── 正弦编码中旋转矩阵的"觉醒"
      │  优势：统一绝对+相对、KV 缓存兼容、不改变范数
      │  问题：外推需要额外技巧
      ▼
2022  ALiBi 线性偏置
      │  优势：完美外推、极简
      │  问题：表达能力有限
      ▼
2023  RoPE 长度扩展 (PI → NTK → YaRN)
      │  逐步解决 RoPE 的外推问题
      ▼
2024  CoPE 上下文位置编码
      │  位置由内容决定
2024  DeepSeek MLA + 解耦 RoPE
      │  RoPE 与 KV 压缩共存
      ▼
2024+ 多维 RoPE (视觉语言模型)
         2D/3D/4D 位置编码
```

## 🔮 位置编码的未来方向

1. **信号处理启发**：小波变换、分层编码——不同粒度的位置信息用不同方式编码
2. **量化鲁棒性**：在低精度（INT4/INT8）计算下仍保持有效的位置编码
3. **内容感知**：位置编码不仅依赖索引，还依赖上下文内容（CoPE 的方向）
4. **多模态统一**：一套位置编码方案同时处理文本、图像、视频、3D 等多模态数据
5. **动态长度**：无需任何长度扩展技巧，天然支持任意长度序列
